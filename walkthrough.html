📋 Student Feedback System — Project Report

Project: Student Feedback Collection & Analysis System Developer: Keshav Kalani Date: February 2026

1. System Overview

A web-based feedback collection system that enables students to anonymously rate teachers on Theory and Practical subjects. The system manages the complete feedback lifecycle — from session creation and form allocation to anonymous submission, report generation, and HOD approval.

Key Capabilities

Capability Description
Multi-role access Admin, Teacher, Student, and HOD — each with dedicated portals
Anonymous feedback Token-based system ensures student identity is never linked to ratings
Elective support Students can be assigned different divisions/batches for elective subjects
Report workflow Teacher agrees → HOD approves — structured approval chain
Batch operations CSV upload for students, teachers, and subjects
Real-time control Admin can start, pause, and terminate sessions at any time

6. Anonymous Feedback Flow

The system ensures complete anonymity through a token-based mechanism:

sequenceDiagram
    participant S as Student
    participant SRV as Server
    participant DB as Database

    S->>SRV: Request token (session_id)
    SRV->>DB: Generate 8-char random token
    SRV->>DB: Store in ValidToken + ActiveTokenMap
    SRV-->>S: Display token on dashboard

    Note over S: Student notes token, goes to feedback form

    S->>SRV: Enter token at gate
    SRV->>DB: Verify token matches student+session
    SRV-->>S: Load feedback form with allocated subjects

    S->>SRV: Submit ratings (via AJAX)
    SRV->>DB: Check session still active (status=1)
    SRV->>DB: Store FeedbackResult rows (per question)
    SRV->>DB: Delete ActiveTokenMap (breaks the link)
    SRV->>DB: Mark TokenLog.is_submitted = True
    SRV-->>S: Success confirmation

Key privacy guarantee: After submission, the ActiveTokenMap record linking the student to their token is deleted. The feedback results are stored against the allocationID (teacher+subject), not the student. There is no way to trace which student gave which rating.

7. Security Features

Feature Implementation
Password Hashing pbkdf2:sha256 via Werkzeug — never stored in plaintext
CSRF Protection Flask-WTF CSRFProtect on all forms and AJAX endpoints
Role-based Access Every route checks session['role'] before serving
Session Validation Feedback submission re-checks session status (prevents submission to closed sessions)
Delete Confirmation Admin password required for teacher/subject deletion
Environment Variables DB credentials stored in .env, loaded via python-dotenv
SQL Injection Prevention SQLAlchemy ORM parameterized queries throughout
Cascade Deletes ondelete='CASCADE' ensures referential integrity
Token Uniqueness Unique constraint on ActiveTokenMap.tokenCode

9. Performance Optimizations

All database query patterns were analyzed and optimized to eliminate N+1 query problems — a common ORM anti-pattern where N additional queries are fired inside a loop.

Before vs After

Route Before After Improvement
Admin Allocations ~150 queries (50 items) ~8 queries ~95% reduction
Admin Manage Sessions N queries (1/session) 1 query ~95% reduction
Admin View Results N queries (1/session) 1 query ~95% reduction
Student Dashboard ~40+ queries ~6 queries ~85% reduction
Teacher Dashboard N queries (1/session) 1 query ~95% reduction
Teacher View Results N queries (1/session) 1 query ~95% reduction
HOD View Results N queries (1/session) 1 query ~95% reduction
HOD Session Teachers 2N queries (2/teacher) 2 queries ~90% reduction

Optimization Techniques Used

  1. Eager Loading (joinedload) — pre-load related objects in a single SQL JOIN instead of lazy-loading per item
  2. Batch Aggregate Queries — SELECT ... GROUP BY to count in one query, stored in Python dicts for O(1) lookup
  3. Bulk Fetching — fetch all related records once, group in Python instead of querying per loop iteration
  4. Database Indexes — 19 indexes on foreign keys and frequently-filtered columns

11. Feedback Questions

Theory Subjects (7 questions)

  1. Lectures were conducted on time and in time uniformly during the term?
  2. Presentation, speed and confidence in delivery of lectures?
  3. Lectures started with a review of the last and ended with a summary of the present?
  4. Clarity in technical concepts, ideas and relevant examples during lectures?
  5. Percentage of university syllabus was covered in the class?
  6. Faculty was available to solve difficulties, motivated to learn the engineering concepts?
  7. Do you understand the lectures delivered by the teacher?

Practical Subjects (6 questions)

  1. Display a list of experiments?
  2. Equipment and support facilities?
  3. Assessment of the experiments performed & journals checked on time?
  4. Support during the lab session?
  5. Additional technical content beyond syllabus covered during the practical session?
  6. Were lab manuals self-explanatory?
